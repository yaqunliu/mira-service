# 小说上传与存储流程设计文档

## 概述

本流程采用**同步接收 + 异步处理**的架构设计，以提高系统响应速度和稳定性。整个流程分为两个阶段：API快速响应阶段和后台任务处理阶段。

---

## 阶段一：同步接收（API快速响应）

### 1.1 API端点定义

**端点**: `POST /api/v1/novels/upload`

**请求参数**:
- `file`: `UploadFile` - 小说文件（.txt格式）
- `Authorization`: Bearer Token - 用户认证令牌(当前未实现登录认证逻辑，默认使用用户名为admin的用户)

**响应格式**:
```json
{
  "task_id": "uuid-string",
  "message": "文件已接收，正在处理中",
  "status": "processing"
}
```

**HTTP状态码**: `202 Accepted`

### 1.2 处理步骤

1. **文件验证**
   - 验证文件格式（仅接受.txt文件）
   - 验证文件大小（建议限制：最大50MB）
   - 验证用户权限（需要登录用户）

2. **临时存储**
   - 将上传文件保存到临时目录：`/tmp/novels/{user_id}/{timestamp}_{filename}.txt`
   - 记录临时文件路径

3. **任务投递**
   - 创建Celery异步任务
   - 任务参数包含：
     - `user_id`: 当前用户ID
     - `temp_file_path`: 临时文件路径
     - `original_filename`: 原始文件名
   - 返回任务ID给前端

4. **错误处理**
   - 文件格式错误 → `400 Bad Request`
   - 文件过大 → `413 Payload Too Large`
   - 未授权 → `401 Unauthorized`
   - 存储失败 → `500 Internal Server Error`

## 阶段二：异步处理（Celery任务队列）

### 2.1 任务函数定义

**函数名**: `process_novel_upload`

**参数**:
```python
{
    "user_id": int,
    "temp_file_path": str,
    "original_filename": str
}
```

### 2.2 处理流程

#### 步骤1: 文件读取
- 从临时存储位置读取小说文件
- 使用UTF-8编码读取（处理中文内容）
- 捕获文件读取异常

#### 步骤2: 小说解析

**2.2.1 元数据提取**
- 解析小说标题：从文件第一行或文件名提取
- 解析作者信息：从文件头部或元数据区域提取
- 如果无法提取，使用默认值：
  - 标题：使用文件名（去除扩展名）
  - 作者：`"未知"`

**2.2.2 章节分割规则**
- 识别章节标题模式：
  - 中文：`第[一二三四五六七八九十百千万\d]+章`
  - 中文变体：`第[0-9]+章`、`第[0-9]+回`
  - 英文：`Chapter\s+[0-9]+`、`CHAPTER\s+[0-9]+`
- 每个章节包含：
  - 章节标题（匹配到的标题行）
  - 章节内容（从标题行到下一个标题行之间的所有文本）

#### 步骤3: 数据库预创建

**3.1 创建小说主记录**
- 在`novels`表中创建记录
- 字段设置：
  - `title`: 解析得到的小说标题
  - `author`: 解析得到的作者（可为空）
  - `owner_id`: 用户ID（未登录用户默认用用户ID：1）
  - `status`: `"processing"`（处理中）
  - `chapter_count`: `0`（初始值，后续更新）
- 获取生成的`novel_id`

#### 步骤4: US3存储与数据库写入循环

对每个解析得到的章节执行以下操作：

**4.1 内容存储到US3**
- 文件路径规范：`novels/{novel_id}/chapter_{chapter_index:04d}.txt`
- 示例：`novels/123/chapter_0001.txt`
- 使用`US3Client.upload_file()`方法上传
- 获取US3返回的文件URL或Key，存储在`content_url`字段

**4.2 元数据存储到PostgreSQL**
- 在`chapters`表中创建记录
- 字段设置：
  - `novel_id`: 所属小说ID
  - `title`: 章节标题
  - `chapter_number`: 章节序号（从1开始）
  - `content_url`: US3文件路径/URL（关键字段）
  - `word_count`: 章节字数（可选，统计文本长度）

**4.3 批量处理优化**
- 建议每处理10个章节后提交一次数据库事务
- 避免单个章节失败导致全部回滚

#### 步骤5: 状态更新

- 更新小说主记录：
  - `status`: `"completed"`（已完成）
  - `chapter_count`: 实际创建的章节数量
  - `updated_at`: 当前时间戳

#### 步骤6: 清理临时文件

- 删除临时存储的文件

#### 步骤7: 错误处理与回滚

- 如果处理过程中发生错误：
  - 更新小说状态为`"failed"`
  - 记录错误信息到日志
  - 清理已创建的部分数据（可选，或保留部分章节）
  - 发送错误通知（可选）

## 数据模型

### Novel模型（`app/models/novel.py`）

```python
class Novel(Base):
    novel_id: int (主键)
    title: str (必填)
    author: str (可选)
    chapter_count: int (默认0)
    status: str (默认"uploaded", 可选值: "uploaded", "processing", "completed", "failed")
    owner_id: int (外键 -> users.user_id)
    created_at: datetime
    updated_at: datetime
```

### Chapter模型（`app/models/chapter.py`）

```python
class Chapter(Base):
    chapter_id: int (主键)
    title: str (必填)
    content_url: str (US3文件路径/URL，关键字段)
    chapter_number: int (必填，章节序号)
    word_count: int (默认0)
    novel_id: int (外键 -> novels.novel_id)
    created_at: datetime
```

## 技术实现要点

### 1. Celery任务配置

- 任务队列：使用Redis或RabbitMQ作为消息代理
- 任务重试：失败任务自动重试3次，间隔递增
- 任务超时：设置任务超时时间为30分钟

### 2. US3存储配置

- 使用`app/utils/us3.py`中的`US3Client`类
- 配置项从`app/core/config.py`读取：
  - `US3_PUBLIC_KEY`
  - `US3_PRIVATE_KEY`
  - `US3_BUCKET_NAME`
  - `US3_UPLOAD_SUFFIX`
  - `US3_DOWNLOAD_SUFFIX`

### 3. 章节解析正则表达式

```python
# 中文章节匹配
chapter_pattern_cn = r'第[一二三四五六七八九十百千万\d]+章|第[0-9]+章|第[0-9]+回'

# 英文章节匹配
chapter_pattern_en = r'Chapter\s+[0-9]+|CHAPTER\s+[0-9]+'
```

### 4. 文件编码处理

- 优先尝试UTF-8编码
- 如果失败，尝试GBK编码（处理中文Windows系统生成的文件）
- 如果都失败，抛出编码错误异常

### 5. 前端轮询机制（可选）

- 前端可通过`GET /api/v1/novels/{novel_id}`查询小说状态
- 状态字段`status`用于判断处理进度：
  - `"processing"`: 处理中，前端显示进度
  - `"completed"`: 处理完成，前端显示成功
  - `"failed"`: 处理失败，前端显示错误信息

## 错误处理规范

### 同步阶段错误
- `400 Bad Request`: 文件格式错误、参数缺失
- `401 Unauthorized`: 未登录或token无效
- `413 Payload Too Large`: 文件大小超限
- `500 Internal Server Error`: 服务器内部错误

### 异步阶段错误
- 记录到日志文件：`logs/app.log`
- 更新数据库状态：`status = "failed"`
- 可选：发送错误通知给用户

---

## 性能优化建议

1. **批量数据库操作**: 使用批量插入减少数据库交互次数
2. **并发处理**: 多个章节可并行上传到US3（使用asyncio或线程池）
3. **进度跟踪**: 在任务中记录处理进度，前端可查询
4. **缓存机制**: 对频繁查询的小说元数据进行缓存
