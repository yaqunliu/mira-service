# 数据库设计文档

## 一、概述

本文档描述 AI 视频生成系统的数据库设计，包括所有数据表的结构、关系和约束。

## 二、数据库技术栈

- **数据库**：PostgreSQL 12+
- **ORM**：SQLAlchemy
- **迁移工具**：Alembic

## 三、实体关系图

```
User (用户)
├── Novel (小说)
│   ├── Chapter (章节)
│   └── Character (角色)
│
└── Creation (创作)
    ├── Character (角色)
    ├── Scene (场景)
    │   └── Shot (分镜)
    │       └── Character (角色) [多对多]
```

## 四、数据表设计

### 4.1 users（用户表）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `user_id` | INTEGER | PRIMARY KEY, INDEX | 用户ID |
| `username` | VARCHAR(50) | UNIQUE, NOT NULL, INDEX | 用户名 |
| `email` | VARCHAR(100) | UNIQUE, NOT NULL | 邮箱 |
| `hashed_password` | VARCHAR(255) | NOT NULL | 加密后的密码 |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 更新时间 |

**关系**：
- 一对多：`users` → `novels` (一个用户可以有多个小说)
- 一对多：`users` → `creations` (一个用户可以有多个创作)

---

### 4.2 novels（小说表）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `novel_id` | INTEGER | PRIMARY KEY, INDEX | 小说ID |
| `title` | VARCHAR(200) | NOT NULL, INDEX | 小说标题 |
| `author` | VARCHAR(100) | | 作者 |
| `chapter_count` | INTEGER | DEFAULT 0 | 章节数量 |
| `status` | VARCHAR(20) | DEFAULT 'uploaded' | 状态：uploaded, processing, completed, failed |
| `task_id` | VARCHAR(100) | INDEX | Celery任务ID（用于查询上传任务状态） |
| `owner_id` | INTEGER | FOREIGN KEY → users.user_id, NOT NULL | 所有者ID |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 更新时间 |

**关系**：
- 多对一：`novels` → `users` (一个小说属于一个用户)
- 一对多：`novels` → `chapters` (一个小说有多个章节)
- 一对多：`novels` → `creations` (一个小说可以有多个创作)
- 一对多：`novels` → `characters` (一个小说可以有多个角色)

**索引**：
- `novel_id` (主键索引)
- `title` (用于搜索)
- `owner_id` (外键索引)
- `task_id` (用于查询任务状态)

---

### 4.3 chapters（章节表）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `chapter_id` | INTEGER | PRIMARY KEY, INDEX | 章节ID |
| `title` | VARCHAR(200) | NOT NULL | 章节标题 |
| `content_url` | VARCHAR(500) | | 章节内容URL（存储在US3） |
| `chapter_number` | INTEGER | NOT NULL | 章节序号 |
| `word_count` | INTEGER | DEFAULT 0 | 字数 |
| `preview` | VARCHAR(100) | | 章节内容预览（前30个字） |
| `novel_id` | INTEGER | FOREIGN KEY → novels.novel_id, NOT NULL | 所属小说ID |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |

**关系**：
- 多对一：`chapters` → `novels` (一个章节属于一个小说)
- 一对多：`chapters` → `creations` (一个章节可以有多个创作)

**索引**：
- `chapter_id` (主键索引)
- `novel_id` (外键索引)

**说明**：
- `content_url` 存储章节内容在 US3 云存储中的路径，而不是直接存储文本内容
- `preview` 字段用于快速预览，避免频繁访问云存储

---

### 4.4 creations（创作表）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `creation_id` | INTEGER | PRIMARY KEY, INDEX | 创作ID |
| `title` | VARCHAR(200) | NOT NULL, INDEX | 创作标题 |
| `status` | VARCHAR(20) | DEFAULT 'created' | 状态：created, playbook_generated, character_generated, scene_generated, audio_generated, video_synthesized, completed, failed |
| `video_url` | VARCHAR(500) | | 最终视频URL |
| `audio_url` | VARCHAR(500) | | 最终音频URL（合并后的完整音频） |
| `subtitle_url` | VARCHAR(500) | | 字幕文件URL（SRT格式） |
| `voice_id` | VARCHAR(100) | | Fish Audio 语音模型ID |
| `voice_speed` | FLOAT | DEFAULT 1.0, NOT NULL | 语速设置，范围 0-10 |
| `owner_id` | INTEGER | FOREIGN KEY → users.user_id, NOT NULL | 所有者ID |
| `novel_id` | INTEGER | FOREIGN KEY → novels.novel_id, NOT NULL | 关联小说ID |
| `chapter_id` | INTEGER | FOREIGN KEY → chapters.chapter_id, NOT NULL | 关联章节ID |
| `current_task_id` | VARCHAR(100) | INDEX | 当前正在执行的任务ID |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 更新时间 |

**关系**：
- 多对一：`creations` → `users` (一个创作属于一个用户)
- 多对一：`creations` → `novels` (一个创作关联一个小说)
- 多对一：`creations` → `chapters` (一个创作关联一个章节)
- 一对多：`creations` → `characters` (一个创作有多个角色)
- 一对多：`creations` → `scenes` (一个创作有多个场景)

**索引**：
- `creation_id` (主键索引)
- `title` (用于搜索)
- `owner_id` (外键索引)
- `novel_id` (外键索引)
- `chapter_id` (外键索引)
- `current_task_id` (用于查询任务状态)

**状态流转**：
```
created → playbook_generated → character_generated → scene_generated → 
audio_generated → video_synthesized → completed
```

---

### 4.5 characters（角色表）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `character_id` | INTEGER | PRIMARY KEY, INDEX | 角色ID |
| `name` | VARCHAR(100) | NOT NULL, INDEX | 角色名称 |
| `status` | VARCHAR(20) | DEFAULT 'new' | 状态：new, generated, confirmed |
| `basic_info` | VARCHAR(500) | | 基本信息描述 |
| `appearance` | TEXT | | 外貌描述 |
| `body` | TEXT | | 身材描述 |
| `hair` | TEXT | | 发型描述 |
| `clothing` | TEXT | | 服装描述 |
| `tags` | ARRAY[VARCHAR] | | 特征标签（字符串数组） |
| `image_prompt` | TEXT | | 图片生成提示词 |
| `visual_style` | VARCHAR(100) | | 视觉风格 |
| `image_url` | VARCHAR(500) | | 角色图片URL |
| `novel_id` | INTEGER | FOREIGN KEY → novels.novel_id | 关联小说ID（可选） |
| `creation_id` | INTEGER | FOREIGN KEY → creations.creation_id | 关联创作ID（可选） |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 更新时间 |

**关系**：
- 多对一：`characters` → `novels` (一个角色可以关联一个小说，可选)
- 多对一：`characters` → `creations` (一个角色属于一个创作，可选)
- 多对多：`characters` ↔ `shots` (一个角色可以出现在多个分镜中)

**索引**：
- `character_id` (主键索引)
- `name` (用于搜索)
- `novel_id` (外键索引)
- `creation_id` (外键索引)

**说明**：
- 角色可以同时关联小说和创作，也可以只关联其中一个
- `tags` 使用 PostgreSQL 的 ARRAY 类型存储多个标签

## 五、数据关系说明

### 5.1 用户与内容的关系

```
User
├── Novel (用户上传的小说)
│   └── Chapter (小说的章节)
│
└── Creation (用户创建的视频项目)
    ├── Character (创作中的角色)
    ├── Scene (创作中的场景)
    │   └── Shot (场景中的分镜)
    └── Novel (关联的小说)
        └── Chapter (关联的章节)
```

### 5.2 角色与分镜的关系

- **角色可以关联到小说**：小说级别的角色库
- **角色可以关联到创作**：创作级别的角色
- **分镜可以关联多个角色**：一个分镜中可以出现多个角色
- **角色可以出现在多个分镜中**：同一个角色可以在不同分镜中出现

### 5.3 创作流程与状态

创作的状态字段反映了视频生成的流程：

1. **created**：创作已创建
2. **playbook_generated**：剧本已生成（场景和分镜）
3. **character_generated**：角色图片已生成
4. **scene_generated**：场景已生成（分镜图片已生成）
5. **audio_generated**：音频已生成
6. **video_synthesized**：视频已合成
7. **completed**：全部完成
8. **failed**：失败

## 六、索引设计

### 6.1 主键索引

所有表都有主键索引，用于快速查找。

### 6.2 外键索引

所有外键字段都建立了索引，用于：
- 快速关联查询
- 级联删除/更新

### 6.3 业务索引

- `novels.title`：用于小说标题搜索
- `novels.task_id`：用于查询上传任务状态
- `creations.title`：用于创作标题搜索
- `creations.current_task_id`：用于查询当前任务状态
- `characters.name`：用于角色名称搜索

## 七、数据存储策略

### 7.1 文本内容存储

- **章节内容**：存储在 US3 云存储，数据库中只存储 URL
- **分镜描述/旁白**：直接存储在数据库中（TEXT 类型）

### 7.2 媒体文件存储

所有媒体文件（图片、音频、视频）都存储在 US3 云存储，数据库中只存储 URL：
- 角色图片：`characters/{character_id}/image_{uuid}.png`
- 分镜图片：`creations/{creation_id}/shots/{shot_id}/image_{uuid}.png`
- 分镜音频：`creations/{creation_id}/shots/{shot_id}/audio_{uuid}.mp3`
- 合并音频：`creations/{creation_id}/merged_audio_{uuid}.mp3`
- 字幕文件：`creations/{creation_id}/subtitle_{uuid}.srt`
- 最终视频：`creations/{creation_id}/video_{uuid}.mp4`

### 7.3 任务ID存储

- `novels.task_id`：存储小说上传任务的 Celery 任务ID
- `creations.current_task_id`：存储当前正在执行的任务ID（用于防止并发任务）

## 八、数据库迁移

系统使用 Alembic 进行数据库迁移管理：

- **迁移文件位置**：`alembic/versions/`
- **迁移命令**：
  ```bash
  # 创建迁移
  alembic revision --autogenerate -m "描述"
  
  # 执行迁移
  alembic upgrade head
  
  # 回滚迁移
  alembic downgrade -1
  ```

## 九、数据完整性约束

### 9.1 外键约束

所有外键都设置了 `NOT NULL` 约束（除了可选的外键），确保数据完整性。

### 9.2 级联删除

- `novels` → `chapters`：级联删除（删除小说时删除所有章节）
- `creations` → `scenes`：级联删除（删除创作时删除所有场景）
- `scenes` → `shots`：级联删除（删除场景时删除所有分镜）

### 9.3 唯一性约束

- `users.username`：用户名唯一
- `users.email`：邮箱唯一

## 十、性能优化建议

1. **分页查询**：对于列表查询，使用分页避免一次性加载大量数据
2. **索引优化**：根据实际查询场景添加合适的索引
3. **查询优化**：使用 `selectinload` 或 `joinedload` 优化关联查询
4. **数据归档**：对于历史数据，考虑归档策略

## 十一、备份与恢复

建议定期备份数据库：

```bash
# 备份
pg_dump -U postgres video_generator > backup.sql

# 恢复
psql -U postgres video_generator < backup.sql
```
