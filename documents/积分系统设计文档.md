# 积分系统设计文档

## 一、功能概述

本文档描述积分系统的设计与实现，包括：

1. **积分账户管理**：用户积分余额、积分类型、过期机制、冻结机制
2. **积分获取**：注册赠送、每日签到、充值（预留）、任务奖励（预留）
3. **积分消耗**：创作相关操作的积分扣除（预扣/后扣机制、冻结机制）
4. **积分记录**：完整的积分变动记录，支持多维度查询
5. **积分查询API**：余额查询、消耗记录查询、统计信息、积分检查
6. **前端集成**：API调用指南和集成示例

## 三、数据库设计

### 3.1 points_accounts（积分账户表）

存储用户的积分账户信息，支持长期积分和临时积分分离。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `account_id` | INTEGER | PRIMARY KEY, INDEX | 账户ID |
| `user_id` | INTEGER | FOREIGN KEY → users.user_id, UNIQUE, NOT NULL, INDEX | 用户ID（唯一） |
| `total_points` | INTEGER | DEFAULT 0, NOT NULL | 总积分余额 = permanent_points + 未过期的临时积分 |
| `available_points` | INTEGER | DEFAULT 0, NOT NULL | 可用积分（总积分 - 冻结积分） |
| `frozen_points` | INTEGER | DEFAULT 0, NOT NULL | 冻结积分（用于任务提交时预扣） |
| `permanent_points` | INTEGER | DEFAULT 0, NOT NULL | 长期积分（不会过期的积分） |
| `created_at` | TIMESTAMP | DEFAULT NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | ON UPDATE NOW() | 更新时间 |

**关系**：
- 一对一：`points_accounts` → `users` (一个用户只有一个积分账户)
- 一对多：`points_accounts` → `points_records` (一个账户有多条积分记录)
- 一对多：`points_accounts` → `temporary_points` (一个账户有多条临时积分记录)

**说明**：
- 用户注册时自动创建积分账户
- `total_points` = `permanent_points` + 未过期的临时积分（从 `temporary_points` 表查询）
- `available_points` = `total_points` - `frozen_points`
- 支持负积分（用于后扣机制）

---

### 3.2 points_records（积分记录表）

记录所有积分变动，包括获取、消耗、过期、冻结、释放等。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `record_id` | INTEGER | PRIMARY KEY, INDEX | 记录ID |
| `account_id` | INTEGER | FOREIGN KEY → points_accounts.account_id, NOT NULL, INDEX | 账户ID |
| `user_id` | INTEGER | FOREIGN KEY → users.user_id, NOT NULL, INDEX | 用户ID（冗余，便于查询） |
| `record_type` | VARCHAR(20) | NOT NULL, INDEX | 记录类型：consume（消耗）、recharge（充值）、reward（奖励）、refund（退款）、expire（过期）、checkin（签到）、freeze（冻结）、release（释放） |
| `operation_type` | VARCHAR(50) | INDEX | 操作类型：create_creation（创建创作）、generate_character（生成角色）、generate_shot（生成分镜）、generate_audio（生成音频）、generate_video（生成视频）、upload_novel（上传小说）、llm_call（大模型调用）、register（注册）、daily_checkin（每日签到） |
| `points` | INTEGER | NOT NULL | 积分变动数量（正数表示增加，负数表示减少） |
| `points_type` | VARCHAR(20) | DEFAULT 'normal' | 积分类型：normal（普通积分）、daily_checkin（每日签到积分，会过期） |
| `expires_at` | TIMESTAMP | INDEX | 过期时间（NULL表示不过期，用于每日签到积分） |
| `balance_before` | INTEGER | NOT NULL | 变动前余额 |
| `balance_after` | INTEGER | NOT NULL | 变动后余额 |
| `creation_id` | INTEGER | FOREIGN KEY → creations.creation_id, INDEX | 关联创作ID（可选） |
| `novel_id` | INTEGER | FOREIGN KEY → novels.novel_id, INDEX | 关联小说ID（可选） |
| `description` | VARCHAR(500) | | 描述/备注 |
| `extra_data` | JSONB | | 扩展信息（JSON格式，存储额外信息，如：视频片段数、音频时长、字数、shot_id、character_id等） |
| `created_at` | TIMESTAMP | DEFAULT NOW(), INDEX | 创建时间 |

**关系**：
- 多对一：`points_records` → `points_accounts` (多条记录属于一个账户)
- 多对一：`points_records` → `users` (多条记录属于一个用户)
- 多对一：`points_records` → `creations` (可选，关联创作)
- 多对一：`points_records` → `novels` (可选，关联小说)

**索引**：
- `account_id` (外键索引)
- `user_id` (外键索引，用于用户查询)
- `record_type` (用于按类型筛选)
- `operation_type` (用于按操作类型筛选)
- `creation_id` (用于按创作筛选)
- `novel_id` (用于按小说筛选)
- `created_at` (用于按时间筛选)
- `expires_at` (用于查询即将过期的积分，已废弃，临时积分使用 temporary_points 表)

**说明**：
- `points` 字段：正数表示增加，负数表示减少
- `points_type` 用于区分普通积分和会过期的积分（已废弃，临时积分使用 temporary_points 表）
- `expires_at` 为 NULL 表示不过期，有值表示会在指定时间过期（已废弃，临时积分使用 temporary_points 表）
- `extra_data` 字段存储 JSON 数据，如：`{"shot_count": 10, "audio_duration": 300, "word_count": 5000, "shot_id": 123}`

### 3.3 temporary_points（临时积分表）

**新增表**：独立存储会过期的临时积分（如签到、活动等），简化扣除逻辑。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `temp_id` | INTEGER | PRIMARY KEY, INDEX | 临时积分ID |
| `account_id` | INTEGER | FOREIGN KEY → points_accounts.account_id, NOT NULL, INDEX | 账户ID |
| `user_id` | INTEGER | FOREIGN KEY → users.user_id, NOT NULL, INDEX | 用户ID（冗余，便于查询） |
| `points` | INTEGER | NOT NULL | 积分数量（正数，扣除时会减少） |
| `source_type` | VARCHAR(20) | NOT NULL, INDEX | 来源类型：checkin（签到）、activity（活动）等 |
| `source_id` | INTEGER | NULLABLE | 来源ID（如关联的 PointsRecord.record_id，活动ID等） |
| `expires_at` | TIMESTAMP | NOT NULL, INDEX | 过期时间（必须） |
| `expire_record_id` | INTEGER | FOREIGN KEY → points_records.record_id, NULLABLE, INDEX | 关联的过期记录ID（如果已创建过期记录，用于避免重复创建） |
| `created_at` | TIMESTAMP | DEFAULT NOW(), INDEX | 创建时间 |

**关系**：
- 多对一：`temporary_points` → `points_accounts` (多条记录属于一个账户)
- 多对一：`temporary_points` → `users` (多条记录属于一个用户)

**索引**：
- `account_id` (外键索引)
- `user_id` (外键索引，用于用户查询)
- `source_type` (用于按来源类型筛选)
- `expires_at` (用于查询即将过期的积分，按过期时间排序)
- `expire_record_id` (用于查询是否已创建过期记录)

**说明**：
- 所有会过期的积分都存储在 `temporary_points` 表中
- 扣除时优先从 `temporary_points` 表扣除，按 `expires_at` 升序（最早过期的先扣除）
- 扣除时直接减少 `points` 字段，如果 `points` 为 0 则删除记录
- `source_type` 用于区分不同来源的临时积分（如签到、活动等）
- `source_id` 可以关联到 `PointsRecord.record_id` 或其他业务对象ID
- `expire_record_id` 用于记录已创建的过期记录ID，避免重复创建过期记录
  - 当临时积分过期且 `expire_record_id` 为 NULL 时，系统会在查询用户可用积分时自动创建过期记录
  - 如果 `expire_record_id` 不为 NULL，说明已经创建过过期记录，不会重复创建

## 五、数据模型

### 5.1 PointsAccount 模型

```python
class PointsAccount(Base):
    """积分账户模型"""
    __tablename__ = "points_accounts"
    
    account_id = Column(Integer, primary_key=True, index=True)
    user_id = Column(Integer, ForeignKey("users.user_id"), unique=True, nullable=False, index=True)
    total_points = Column(Integer, default=0, nullable=False)  # 总积分 = permanent_points + 未过期的临时积分
    available_points = Column(Integer, default=0, nullable=False)  # 可用积分 = total_points - frozen_points
    frozen_points = Column(Integer, default=0, nullable=False)  # 冻结积分
    permanent_points = Column(Integer, default=0, nullable=False)  # 长期积分（不会过期的积分）
    
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), onupdate=func.now())
    
    # 关系
    user = relationship("User", back_populates="points_account")
    records = relationship("PointsRecord", back_populates="account", order_by="PointsRecord.created_at.desc()")
    temporary_points = relationship("TemporaryPoints", back_populates="account", order_by="TemporaryPoints.expires_at.asc")
```

### 5.3 PointsRecord 模型

```python
class PointsRecord(Base):
    """积分记录模型"""
    __tablename__ = "points_records"
    
    record_id = Column(Integer, primary_key=True, index=True)
    account_id = Column(Integer, ForeignKey("points_accounts.account_id"), nullable=False, index=True)

    record_type = Column(String(20), nullable=False, index=True)  # consume, recharge, reward, refund, expire, checkin, freeze, release
    operation_type = Column(String(50), index=True)  # create_creation, generate_character, etc.
    
    points = Column(Integer, nullable=False)  # 正数增加，负数减少
    points_type = Column(String(20), default="normal")  # normal, daily_checkin
    expires_at = Column(DateTime(timezone=True), index=True, nullable=True)
    
    balance_before = Column(Integer, nullable=False)
    balance_after = Column(Integer, nullable=False)
    
    creation_id = Column(Integer, ForeignKey("creations.creation_id"), index=True, nullable=True)
    novel_id = Column(Integer, ForeignKey("novels.novel_id"), index=True, nullable=True)
    
    description = Column(String(500))
    extra_data = Column(JSON)  # PostgreSQL JSONB 类型
    
    created_at = Column(DateTime(timezone=True), server_default=func.now(), index=True)
    
    # 关系
    account = relationship("PointsAccount", back_populates="records")
    user = relationship("User")
    creation = relationship("Creation")
    novel = relationship("Novel")
```

| `audio_duration_seconds` | float | 否 | 音频时长（秒，音频生成时使用） |
| `audio_model_name` | string | 否 | 音频模型名称（音频生成时使用） |
| `shot_count` | int | 否 | 视频片段数（视频生成时必填） |
| `image_count` | int | 否 | 图片数量（图片生成时必填） |
| `image_model_name` | string | 否 | 图片模型名称（图片生成时使用） |

**响应示例（积分充足）**：

```json

    "code": 200,
    "data": {
        "available": true,
        "required_points": 35,
        "available_points": 150,

    "message": "检查成功"
}
```

**响应示例（积分不足）**：

```json
{
    "code": 200,
    "data": {
        "available": false,
        "required_points": 100,
        "available_points": 50,
        "message": "积分不足，无法执行操作（需要 100 积分，当前可用 50 积分）"
    },
    "message": "检查成功"
}
```

**响应示例（LLM调用 - 积分充足）**：

```json

        "available": true,
        "required_points": 0,
        "available_points": 150,
        "message": "积分充足，可以调用"
    },
    "message": "检查成功"
}
```

**检查规则**：

- **LLM调用（后付费）**：只要积分 > 0 就可以调用，返回 `required_points = 0`
- **其他操作（预付费）**：
  - 音频生成：按文本字节数计算成本，每1元=100积分
  - 视频生成：每个片段1积分
  - 图片生成：按实际成本计算，每1元=100积分
  - 检查逻辑：`available_points >= required_points && available_points > 0`

## 十二、系统优化和注意事项

### 12.1 已实施的优化

#### ✅ 1. 数据库行锁（防止并发问题）

**实现位置**：`app/services/points_service.py` - `deduct_points()`、`freeze_points()`

**优化内容**：
```python
# 使用 SELECT FOR UPDATE 锁定账户行
account = db.query(PointsAccount).filter(
    PointsAccount.user_id == user_id
).with_for_update().first()
```

**作用**：防止多个请求同时扣除积分导致余额计算错误

#### ✅ 2. 幂等性检查（防止重复扣费）

**实现位置**：
- `app/services/points_service.py` - `check_deduction_exists()`
- `app/services/points_service.py` - `deduct_points()` 中调用

**优化内容**：
- 检查24小时内是否已为同一操作（相同 shot_id 或 character_id）扣除过积分
- 如果已扣除，直接返回已存在的记录，不重复扣除

**作用**：
- 防止任务重试时重复扣费
- 防止强制重新生成时重复扣费
- 防止并发请求重复扣费

#### ✅ 3. 冻结机制（防止多设备并发超额使用）

**实现位置**：`app/services/points_service.py`

**新增方法**：
- `freeze_points()` - 冻结积分（提交任务时调用）
- `confirm_frozen_points()` - 确认扣除（任务成功时调用）
- `release_frozen_points()` - 释放冻结（任务失败时调用）

**作用**：
- 提交任务时立即冻结积分，其他任务无法使用
- 使用数据库行锁，保证并发安全
- 任务失败时自动退回冻结的积分

#### ✅ 4. 退款机制

**实现位置**：`app/services/points_service.py` - `refund_points()`

**功能**：
- 任务失败时可以退回预扣的积分
- 防止重复退款
- 记录退款原因

### 12.2 需要注意的问题

#### ⚠️ 1. 任务重试重复扣费

**问题**：
- Celery任务失败后自动重试
- 如果任务在积分扣除后失败，重试时会再次扣除

**已解决**：
- ✅ 通过幂等性检查，24小时内相同操作不会重复扣费
- ✅ 积分扣除在任务成功后执行，减少失败概率

#### ⚠️ 2. 并发请求重复提交

**问题**：
- 用户快速连续点击"生成"按钮
- 多个请求同时通过积分检查，都提交了任务

**已解决**：
- ✅ 使用数据库行锁防止并发扣除
- ✅ 幂等性检查防止重复扣费
- ✅ 冻结机制防止多设备并发超额使用

**建议**：
- 前端添加防重复提交（防抖、状态管理）
- 后端检查任务状态（`current_task_id`），防止重复提交

#### ⚠️ 3. 任务失败积分未退回

**问题**：
- 预扣积分后，任务执行失败
- 积分已经被扣除，但任务未完成

**当前处理**：
- 积分扣除在任务成功后执行，减少失败概率
- 如果扣除后任务失败，需要手动退款
- 使用冻结机制时，任务失败会自动释放冻结的积分

**建议**：
- 在任务失败时自动退款（需要集成到任务失败处理逻辑）
- 优先使用冻结机制，任务失败时自动退回

#### ⚠️ 4. 强制重新生成重复扣费

**问题**：
- `force_regenerate=True` 时，会重新生成并重复扣费

**已解决**：
- ✅ 幂等性检查会检测到24小时内的重复扣除，不会重复扣费

**注意**：
- 如果用户确实需要重新生成，可能需要等待24小时，或者手动处理

#### ⚠️ 5. LLM调用重复扣费

**问题**：
- LLM调用是后付费，可能多次调用同一接口

**当前处理**：
- LLM调用不检查重复（`check_duplicate=False`），因为可能确实需要多次调用

**建议**：
- 如果需要防止重复，可以在 `extra_data` 中添加唯一标识（如请求ID）

### 12.3 数据一致性检查

#### 12.3.1 定期校验积分余额

```python
def verify_points_balance(db: Session):
    """
    校验积分余额：账户余额 = 所有记录之和
    """
    accounts = db.query(PointsAccount).all()
    for account in accounts:
        # 计算所有记录的总和
        total_from_records = db.query(func.sum(PointsRecord.points)).filter(
            PointsRecord.account_id == account.account_id
        ).scalar() or 0
        
        # 对比账户余额
        if account.total_points != total_from_records:
            logger.error(
                f"积分余额不一致: user_id={account.user_id}, "
                f"账户余额={account.total_points}, "
                f"记录总和={total_from_records}"
            )
```

## 十六、注意事项

1. **并发安全**：积分扣除时需要使用数据库事务和锁机制，避免并发问题
2. **积分过期**：每日签到积分过期时间设置为当天24:00（次日00:00:00），一到24点就失效
3. **负积分处理**：后扣机制允许负积分，但预扣机制不允许
4. **配置灵活性**：积分消耗规则通过配置定义，支持多种计费方式
5. **记录完整性**：所有积分变动都要记录，包括过期、退款、冻结、释放等
6. **性能优化**：积分记录表数据量大时，考虑分表或归档策略
7. **数据一致性**：账户余额 = 所有记录之和，需要定期校验
8. **多设备并发**：使用冻结机制防止多设备并发超额使用
9. **幂等性**：确保同一操作不会重复扣费（24小时窗口检查）
10. **任务失败处理**：任务失败时自动释放冻结的积分或退款
